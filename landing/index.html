为什么普通方法删不掉？

问题出在路径解析阶段，不在文件本身。继续向下滚动页面，看内容从沙粒重新聚拢。

✕ 普通方式

  • 资源管理器、del NUL 操作的都是“NUL 设备”，不是那个真实文件。
  • Win32 API 在解析路径时就把 NUL 识别成 DOS 设备对象。
  • 于是你永远删不到磁盘上那个字面叫 NUL 的文件。

✓ delete-nul

  • 枚举不受影响，可正常列出真实文件名。
  • 给路径加 \\?\ 前缀，跳过 Win32 规范化，直达 NT 对象管理器。
  • 此时它就是字面路径，可以精确删除并复核。

同一串字符，两种解析

WIN32del NUL命中 DOS 设备对象，磁盘上的文件纹丝不动
NTdel \\?\C:\work\NUL跳过规范化，按字面路径精确命中

流程：枚举 → 按名字精确匹配 → 记录完整路径 → 加 \\?\ 前缀删除 → 复核报告。删除不进回收站，先看列表再按 Y。

// FAQ

常见问题

使用前先确认哪些文件会被删除。

闪退 / 被杀软删除？

当前 bat 是调用 ps1 的薄包装，无 Base64、无混淆。若杀软仍拦截"下载并执行"，从项目仓库下载并检查脚本内容，再按你的安全设置决定是否运行。

提示 FAILED 怎么办？

文件被占用或权限不足。关闭占用程序，或删除系统目录时加 -Elevate 以管理员重试。

能恢复吗？

不能。删除不进回收站，务必核对列表后再按 Y。

会误删 nul.txt 吗？

默认不会，只匹配裸名。如需连同带扩展名的保留名一起处理，显式加 -IncludeExtension。

拖到图标显示禁止符号 / 拖进窗口没反应？

前者多为 .bat 被关联到编辑器或拖拽源是压缩包内路径；后者多因 UIPI——脚本默认不提权以避免此问题。两种都可改用菜单里的"粘贴路径"。
